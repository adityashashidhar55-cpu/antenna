Security Practices

Exactly how Antenna is hosted, run, and secured today — described plainly, including what hasn't been formally audited yet.

Last updated: August 6, 2026
1. Hosting & Transport 2. Backend Automation 3. No Stored Passwords 4. Payment Security (Stripe) 5. Audits & Certifications 6. Day-to-Day Practices 7. Reporting an Issue

1. Hosting & Transport

Antenna's frontend is a static site served over HTTPS via GitHub Pages. There's no custom application server rendering pages — what you're browsing is static HTML, CSS, and JavaScript delivered directly by GitHub's infrastructure, with GitHub Pages' standard TLS termination protecting the connection between your browser and the site.

Why this matters: a static site has a much smaller attack surface than a typical dynamic web app — there's no server-side application code on our end that renders your requests, no server-side session store, and no traditional database directly exposed to the internet from the frontend.

2. Backend Automation

The live trend, product, and startup data you see in the dashboard comes from a backend built on n8n cloud, a workflow automation platform. n8n runs the scheduled jobs that gather, process, and store this data, and exposes it to the frontend through a small set of read-only webhook endpoints (for example, the ones checked live on our Status page).

These endpoints are intentionally read-only from the frontend's perspective — the public dashboard reads trend data, it does not write to the underlying data store.

3. No Stored Passwords

Antenna does not implement a traditional username/password login system, which means there's no password database for us to protect — and nothing for an attacker to breach in the way that plagues many SaaS products. Where a paid plan or synced watchlist is tied to your account, access is resolved by looking up your email address against your plan/subscription status, rather than by a password you set with us.

4. Payment Security (Stripe)

All card payments are handled by Stripe through Stripe's own hosted Checkout page — your card details are entered directly into Stripe's interface, not ours. Stripe is a PCI-DSS Level 1 certified payment processor, the highest level of certification in the payment card industry. That certification describes Stripe's own infrastructure; Antenna itself never receives, transmits, or stores your full card number, expiry date, or CVV, which significantly limits our own PCI compliance scope.

5. Audits & Certifications

Stated plainly: Antenna has not completed a formal SOC 2 or ISO 27001 audit. This is a real but early-stage, independently-built product, and we haven't yet gone through a formal third-party security audit or certification process. If a SOC 2, ISO 27001, or similar attestation is a hard requirement for your organization's procurement process, please contact us to discuss your specific requirements — we're happy to have that conversation directly rather than make a claim we can't back up.

6. Day-to-Day Practices

🔐

HTTPS everywhere

The site and all API calls to our backend are made over HTTPS, encrypting data in transit.

🗂️

Minimal data collection

We collect as little personal data as the product needs — see our Privacy Policy for the full, honest list.

🧩

Separated payment scope

Card data handling is fully delegated to Stripe's hosted Checkout, keeping full card numbers out of our systems entirely.

📡

Read-only public API

The public trend/product/startup endpoints the dashboard calls are read-only — they don't accept writes from the browser.

💻

Small, auditable codebase

The frontend is a small set of self-contained static HTML/JS files with no build pipeline, which keeps the shipped code easy to inspect.

📈

Live status transparency

Our Status page runs real, live checks against backend endpoints in your browser — not a static claim of uptime.

7. Reporting a Security Issue

If you believe you've found a security vulnerability in Antenna, please report it responsibly to aditya.shashidhar55@gmail.com. We'll do our best to respond promptly and address confirmed issues — as a small, early-stage project, response times may vary, but we take reports seriously.
